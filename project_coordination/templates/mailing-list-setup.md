# GAIA Mailing Lists — Setup & Opt-in

> Low-cost, voluntary lists on **Google Groups** (free even for the consumer
> `gaia.hazlab@` account) — a real subscribe/unsubscribe list + searchable archive, no paid
> Workspace needed. Two lists, different jobs. Opt-in is genuinely voluntary with one-click
> unsubscribe (the right posture when collecting personal emails).

## 1. The two lists

| List | Address | Who | Traffic | Posting |
|---|---|---|---|---|
| **Announce** | `gaia-announce@googlegroups.com` | anyone who opts in (members, collaborators, community partners) | low — quarterly newsletter + big announcements | **owners only** (one-way) |
| **Team** | `gaia-team@googlegroups.com` | funded members + active collaborators | as needed — logistics, discussion | members can post |

Keep them separate: the community partners and broader audience get **Announce only**; they
never see day-to-day team chatter, and the team list never spams the wider circle.

## 2. Create each list (in `gaia.hazlab@`, at <https://groups.google.com>)

1. **Create group** → name (`GAIA Announce` / `GAIA Team`), email, description.
2. **Who can post:**
   - Announce → **Group owners and managers** (one-way broadcast).
   - Team → **Group members**.
3. **Who can join:** **Only invited users** (you add opt-ins) — *not* "Anyone can join,"
   so the list stays curated and consent-based.
4. **Who can view members / archive:** members only (privacy).
5. **Subscription:** set new members to **"Each email"** for Announce (it's rare) and let
   Team members pick digest.
6. Add the **Lead PI + coordinator as managers/owners** of both, so sending and upkeep
   aren't single-threaded.

## 3. Adding people (consent-first)

- Only add someone to **Announce** if their intake response / roster shows
  `mailing_list_optin = true` ([participant-roster.md](participant-roster.md)).
- Use **"Add members directly"** sparingly (it subscribes without a click) — prefer
  **"Invite members"** so people confirm. For team logistics, direct-add of funded members
  is fine; for the wider Announce list, invite.
- Record the opt-in date in the roster Private tab — that's your consent trail.
- **Every send includes an unsubscribe line** (Groups adds a footer; keep it). Honor
  unsubscribes immediately.

## 4. Opt-in blurb (reuse on the form, onboarding checklist, and website)

> **Stay in the loop — optional.** GAIA sends a short **quarterly newsletter** with project
> highlights, new tools and datasets, upcoming seminars/hackweeks, and community impact
> numbers. It's low-volume and you can unsubscribe anytime. **Want it?** → subscribe at
> [gaia-announce link] or tick "yes" on the intake form.

Short form (for a website footer / Slack pin):

> 📬 *Get the GAIA quarterly newsletter — highlights, tools, events, impact. Optional,
> low-volume, one-click unsubscribe. [Subscribe].*

## 5. What goes to which list

| Content | Announce | Team |
|---|---|---|
| Quarterly newsletter ([quarterly-newsletter.md](quarterly-newsletter.md)) | ✅ | ✅ (or link) |
| New JupyterBook / dataset / model release | ✅ | ✅ |
| Seminar / hackweek invitations | ✅ | ✅ |
| Meeting logistics, agendas, action items | — | ✅ |
| Paper accepted / award / milestone shout-outs | ✅ | ✅ |
| Day-to-day coordination | — | ✅ |

> Prefer **Slack `#weekly-status`** for async operational updates
> ([01 §4](../01-project-coordination.md)); email lists are for things worth landing in an
> inbox, not a replacement for Slack.
